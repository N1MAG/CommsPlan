CommsPlan 2.0.5, formerly FreqInOut — macOS manual DMG replacement

This document describes a manual replacement and recovery procedure. Use a
disposable or separately backed-up station when first exercising it, and retain
the historical application and installer until station verification and rollback
checks are complete. External hardware, companion applications, and keychain
continuity still require operator checks on the selected Mac.
The disk image does not discover, back up or remove an existing installation.
Copying CommsPlan.app alone can leave two apps installed with the same bundle ID.
The historical profile root remains `~/.freqinout` unless
`FREQINOUT_CONFIG_DIR` selects another location. The databases remain
`freqinout.db` and `freqinout_nets.db`, and the bundle identifier remains
`org.n1mag.freqinout`; only the displayed app name and executable use CommsPlan.

BEFORE REPLACEMENT

1. Identify your actual FreqInOut installation and profile. Record their full
   paths, application version, architecture and package checksum. Keep the old
   installer. Do not assume a profile location if FREQINOUT_CONFIG_DIR is set.
   Do not use the source-only migration assistant with a frozen application.

2. In Terminal, inspect the selected old app's identity without launching it:
   /usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' "/FULL/PATH/FreqInOut.app/Contents/Info.plist"
   It must report org.n1mag.freqinout. A matching name or bundle ID alone does
   not prove an official historical release. Stop if the selected app/version
   is uncertain or multiple installations/profile locations are ambiguous.
   Inventory indexed copies with:
   mdfind 'kMDItemCFBundleIdentifier == "org.n1mag.freqinout"'
   Spotlight can omit unindexed disks/folders. Also review your Applications
   folders, custom installation locations and mounted volumes manually. Inspect
   each installation by full path. Stop until ambiguous active copies are resolved;
   a backup copy outside Applications must never be selected as the active app.

3. Quit FreqInOut, CommsPlan and companion applications normally. Confirm their
   processes exited in Activity Monitor. Keep them closed throughout copying.
   Do not force quit during station writes. The disk image cannot enforce this.

4. Create and verify a cold backup of the entire selected station profile in
   a separate location, including both databases, settings and attachments.
   Verify the backup can be restored into a NEW profile with the old version.
   Retain external companion data and the same macOS account/keychain. The
   profile backup does not include keychain secrets. Native 2.0.4 preparation is
   available in the CommsPlan source tree via --migration-preparation; follow the companion
   CommsPlan-migration.md guide with a retained, digest-matching historical DMG
   and NEW JSON reports. Its profile/package verification prepares the recovery
   handoff but does not replace the manual station checks below. Stop without a
   verified recovery copy.

5. Copy the complete old application to a separate recovery folder outside
   Applications. Check its bundle identity/version and verify the copied bundle
   against the original. Preserve signatures, executable permissions and links.
   Retain both the application copy and its original installer/checksum.
   For the app copy, replace the example paths below with confirmed physical
   paths. Use a NEW recovery directory; every destination shown must be absent.
   Do not treat an interrupted ".partial" directory as a complete copy:

   mkdir "/FULL/PATH/NEW_RECOVERY"
   ditto --rsrc --extattr --acl "/FULL/PATH/FreqInOut.app" "/FULL/PATH/NEW_RECOVERY/FreqInOut.app.partial"

   Generate separate file hash inventories from each bundle root:
   (cd "/FULL/PATH/FreqInOut.app" && find . -type f -exec shasum -a 256 {} \; | LC_ALL=C sort) > "/FULL/PATH/NEW_RECOVERY/original.sha256"
   (cd "/FULL/PATH/NEW_RECOVERY/FreqInOut.app.partial" && find . -type f -exec shasum -a 256 {} \; | LC_ALL=C sort) > "/FULL/PATH/NEW_RECOVERY/copy.sha256"
   diff "/FULL/PATH/NEW_RECOVERY/original.sha256" "/FULL/PATH/NEW_RECOVERY/copy.sha256"

   All commands must succeed without read/hash errors and diff must report no
   differences. These hashes cover regular file bytes; also compare symbolic
   link targets and executable permissions and check both bundles' code-signature
   status. An unsigned app does not become signed by copying it. Stop if the
   copy changes signature status or bundle metadata. After these checks only:
   mv -n "/FULL/PATH/NEW_RECOVERY/FreqInOut.app.partial" "/FULL/PATH/NEW_RECOVERY/FreqInOut.app"
   Confirm the final path exists and the .partial path no longer exists. Keep
   the inventory files beside it. Never use an existing destination for a retry.

REPLACE AND VERIFY

6. Check the CommsPlan package checksum/architecture. For the release assets,
   use `CommsPlan-2.0.5-macos-arm64-unsigned.dmg` on Apple Silicon or
   `CommsPlan-2.0.5-macos-x86_64-unsigned.dmg` on Intel. Inspect the app in this
   mounted image: bundle ID org.n1mag.freqinout; executable and name CommsPlan;
   version matches the selected release. Use the release's signing instructions;
   an unsigned package remains unsigned after replacement.

7. Move the selected old application out of its active Applications location
   into a NEW, separately named subfolder of the recovery folder. Do not replace
   the verified application backup made in step 5. Copy CommsPlan.app
   from this image into the selected Applications location. If a CommsPlan.app
   already exists there, STOP and inventory it; do not overwrite blindly. Do
   not remove other apps by filename or bundle ID. Do not start the old copy.

8. Launch the installed CommsPlan explicitly by its full path, using the same
   OS account and selected profile. Do not rely on an old Dock pin or Spotlight
   to select between retained copies. For an explicit profile override, launch
   the installed Contents/MacOS/CommsPlan executable from an environment with
   FREQINOUT_CONFIG_DIR set to the confirmed profile ROOT. Review startup
   automation and isolate radios/companions for the first replacement run.

   A frozen package's startup guard is separate from the manual full-profile
   backup above. Its receipt at
   `<PROFILE_ROOT>/.commsplan-packaged-startup.json` records a verified raw
   `config`-tree backup, including captured SQLite WAL/journal sidecars; it does
   not cover the whole profile, credentials, logs, caches, or companion data. A
   missing receipt is normal on first launch and starts the guarded capture. A
   fully fresh profile is allowed and is recorded as `fresh-profile`; if its
   databases appear later, the guard captures the first verified backup then.
   A malformed, changed, or linked receipt, or a missing or changed recorded
   manifest or backup, stops startup for recovery.

9. A 1.2.8 station still requires the existing informed station-upgrade dialog.
   A completed 2.0.4 station must retain its multi-rig configuration. Verify
   callsign, radios/bindings, companion paths, schedules/groups, messages,
   attachments, preferences and credential access. An installer or shell opening
   successfully is not proof of station continuity. Stop on missing data.

10. After station verification, remove the old Dock shortcut and pin the
    installed CommsPlan. Confirm that it opens the intended executable/profile.
    Retain the old application and verified station backup for recovery; do not
    launch the old application against a station upgraded by the newer app.

INTERRUPTION OR FAILED VERIFICATION

Keep every partial copy and the original backup for review. Do not merge app
bundles, overwrite the sole recovery copy, or infer completion from a filename.
Close all apps. Restore the pre-upgrade station into a NEW profile directory,
verify it, then launch the matching historical app by its full path with that
explicit restored profile. A newer database must not be opened in 1.2.8; restoring
only the old application does not roll back station conversion. Re-establish
the original active app location only after the selected copies are verified.

Native process state, replacement interruption, rollback, Dock/LaunchServices,
and keychain continuity require operator checks on Intel and Apple Silicon; this
procedure does not claim every external hardware path is qualified.
