# Support and diagnostics

Start with the smallest useful set of evidence. Most questions do not require a station database.

## Include with a support request

- CommsPlan version and whether the station was previously FreqInOut.
- Operating system and architecture.
- Package installation or source installation, including the package basename when applicable.
- The affected radio, software family, or mesh connection.
- The exact navigation path where the behavior occurs.
- What you did, what you expected, and what happened instead.
- The relevant log segment and a screenshot when it materially clarifies the state.

## Protect station information

Review every attachment for callsigns, message contents, access codes, local paths, coordinates, and other information you do not want to share. Database files are not normally needed unless support specifically requests them.

## Common diagnostic files

The configured profile root may contain:

- `freqinout.log` — the main application log.
- `perf_metrics.log` — bounded performance observations.
- `fio_cpu_hotspot_*.txt` — CPU hotspot evidence when generated.
- UI-hang evidence generated by the watchdog, when present.

Unless `FREQINOUT_CONFIG_DIR` selects another profile, the normal profile roots are:

| Platform | Default profile root |
|---|---|
| Windows | `%LOCALAPPDATA%\FreqInOut` or `%APPDATA%\FreqInOut` |
| macOS | `~/.freqinout` |
| Linux | `~/.freqinout` |

## Where to ask

- Review the [repository README](https://github.com/N1MAG/CommsPlan#readme).
- Check the [latest release notes](https://github.com/N1MAG/CommsPlan/releases/latest).
- Report a reproducible software defect through [GitHub Issues](https://github.com/N1MAG/CommsPlan/issues).
- For existing support arrangements, email [bill@n1mag.com](mailto:bill@n1mag.com).

When community Discussions are enabled, this page can direct setup and operating questions there while reserving Issues for confirmed defects.
